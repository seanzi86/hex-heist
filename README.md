# HEX//HEIST

A tower-defence game on a hex grid that runs in the browser. Hostile code pours in at the red intrusion point and
heads for your data core. Build towers, bend the route, and survive 20 waves on each of 35 levels, then see how long
you last.

Built with TypeScript, Vite, Preact and a Canvas 2D renderer. There are no image or audio files: the art is drawn in
code and every sound is synthesised with Web Audio.

## Playing

- **Towers:** Ping (cheap and quick), Trace (a beam that pierces everything in a line), Seeker (slow homing missiles),
  Firewall (burns everything around it) and Throttle (chain arcs that slow and zap; unlocks at level 21). Each upgrades
  three times.
- **Enemies:** Worms, fast Spikes, and Trojans that burst into two smaller enemies. Bosses (Prism, Cipher, Interceptor,
  Rootkit) are each immune to one tower type, and the game warns you before a boss wave.
- **Boards:** open fields, lanes and switchbacks with several intrusion points, plus special tiles: repair nodes,
  corrupt sectors, overclock and lag tiles, data streams that force the route, and proxy gates that teleport enemies.
- **The route bends:** towers block tiles, so enemies take the shortest open path. You can lengthen it but never seal
  it. The dashed line shows the route, including a preview while you drag a tower.
- **Two difficulties** (Easy and Hard), a high score per level, and an in-game how-to-play screen.

## Run it

```bash
npm install
npm run dev        # dev server with hot reload (http://localhost:5173)
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build locally
npm run typecheck  # TypeScript only
```

`dist/` is plain static files with relative paths, so it can be hosted anywhere (GitHub Pages, Netlify, any web server).

## Controls

| Action | Input |
|---|---|
| Build (drag) | press a tower in the bottom bar, drag it onto the board, release to place. Release over the bar (or off the board) to cancel. On touch the chip floats above your finger |
| Build (tap) | pick a tower in the bar (or keys `1`-`5`), then tap tiles |
| Select / upgrade / sell | tap a tower |
| Start the next wave | `▶` button, `Space`, or tap the red intrusion point. There is no timer between waves: build as long as you like, then start. Starting sooner earns bonus points (shown on the button) |
| Auto-start waves | `⟳ Auto` button or `A`: each wave begins 3 seconds after the last is cleared |
| Show / hide the route | `⤳` button or `R` |
| Pause / resume | `⏸` button or `P`. A dimmed overlay covers the board with Resume / Restart / Levels; tapping the dark area, `Esc` or `P` resumes. Building, selling and upgrading are blocked while paused. The game also pauses by itself if you switch apps or tabs |
| Speed | `1×` button or `F` cycles 1x / 2x / 3x |
| Cancel | `Esc` |
| How to play | `How to play` on the menu, `Help` on the pause card, or `H` in a game. It also opens automatically the first time you launch |

## Project layout

```
index.html            minimal page: mount point + one script tag
src/
  main.tsx            entry point: wires hooks and renders <App/>
  types.ts            shared types
  constants.ts        geometry, tile codes, palette, rules
  geometry.ts         hex maths helpers
  state.ts            settings + current session
  hooks.ts            callbacks the game rules use to reach the UI
  audio.ts            Web Audio synth engine (noise and tone layers, saturation, reverb, limiter)
  sounds.ts           the sound recipes
  loop.ts             animation frame loop
  styles/global.css   design tokens (CSS variables), reset, base elements
  data/
    levels.ts         assembles the 35 levels: board + waves + calibrated difficulty
    balance.ts        ALL balance numbers: tower stats, enemy health and speed, health/reward curves
    waves.ts          wave lists (one set per block of five levels)
    calibration.ts    per-level enemy-health multiplier and threat pips, GENERATED by the bot
    layouts.ts        the 35 boards, GENERATED by tools/generate-levels.ts
    defs.ts           tower and enemy definitions
  game/               simulation (no DOM): grid + pathing, creeps, towers,
                      projectiles, player actions, engine (waves, scoring)
  render/             canvas drawing: board, towers, creeps, effects
  ui/
    state.ts          UI-only state + notify()/useRefresh() for re-rendering
    controller.ts     play / retry / back-to-menu, and the game->UI hooks
    input.ts          pointer and keyboard handlers
    components/       Preact components, each with its own *.module.css:
                      App, Menu, GameScreen, GameCanvas, Hud, TowerBar,
                      PauseOverlay, Help (+ icons.tsx: SVG tower/enemy/tile icons)
tools/
  generate-levels.ts  level generator (`npm run levels`)
  bot.ts              balance bot (`npm run bot`)
```

**How the UI works.** The simulation (`src/game`) never touches the DOM; it reports to the UI through
`hooks.ts`. The UI is Preact components that read the current game and re-render when `notify()` runs
(on game events, and four times a second for the countdown). The canvas is drawn imperatively by
`src/render`; `GameCanvas` mounts it, starts the loop, and refits it with a `ResizeObserver`.
Styling uses CSS Modules (scoped class names per component) on top of the global tokens.

## Graphics quality

Glow is drawn with pre-rendered glow sprites (cheap). Bloom is an extra pass that blurs the bright parts of the
frame by shrinking and re-scaling it; it costs more, so the game turns it off by itself if the frame rate drops
(see `src/loop.ts`). Open the game with `?fx=low` to start with both glow and bloom off. The switches live in
`src/render/quality.ts`.

## Levels

The 35 boards are generated, not hand-drawn. `npm run levels` reads a recipe for each level (layout style, number of
intrusion points, hazards, data streams, proxy gates) and builds 1,500 random candidate boards per level. It scores
each one for difficulty (number of entrances, route length, build space near the route, hazards) and keeps the one
closest to a rising target. The seed is fixed, so the output is repeatable. It writes `src/data/layouts.ts`; change a
recipe in `tools/generate-levels.ts` and rerun rather than editing that file. `npm run levels -- 21` regenerates and
prints a single level as text.

## Difficulty and balance

Difficulty has three layers: the board layout, the wave list (each block of five levels has its own, see `data/waves.ts`),
and a per-level enemy-health multiplier (`data/calibration.ts`). All numbers (tower stats, enemy health and speed, the
health and reward curves) are in `data/balance.ts`.

`npm run bot` plays every level through the real engine with an automatic player and prints the result:
`npm run bot -- 14` shows one level in detail, `--hard` plays Hard mode, `--skill=good|casual` picks one player.
`npm run bot -- --calibrate` finds the enemy-health multiplier at which the good bot only just wins each level, then sets
each level to a growing fraction of it (about 50% on level 1 up to about 92% on level 35) and writes `calibration.ts`.
Rerun it after changing any balance number or layout. The bot is a rough stand-in for a human: treat its output as a
guide, and levels it flags with `*` (it struggles on those) are worth playing by hand.
